# 16-AWS 消息與資料串流服務

2025-10-12

這份筆記幫助你理解考試中最常出現的 AWS 訊息傳遞與資料串流相關服務的本質與應用場景，強調「你該怎麼判斷用哪個服務」而不是死記細節。

---

## 📣 Amazon SNS（Simple Notification Service）

### 核心概念

* SNS 是 **發佈 / 訂閱型（Pub/Sub）通知服務**。
* 適合用於 **一對多通知廣播** 的場景，例如一個系統事件需要通知多個接收者（email、SMS、SQS queue、Lambda 等）。

### 考試重點

> ✅ **記住：SNS 是用來廣播通知，一對多推送。**

### 常見使用情境

* 當 EC2 異常、Auto Scaling、S3 上傳等事件觸發後，需要通知多方處理系統。
* SNS 可接 **SQS、Lambda、Email、HTTP endpoint** 作為訂閱者。

### 補充功能

* **Message Filtering**：針對不同的訂閱者定義條件，篩選只接收特定訊息類型。
* **FIFO SNS**（2021 年新增）：支援順序性與 Exactly-once 傳遞保證，適合需要順序訊息的場景。

## 📨 Amazon SQS（Simple Queue Service）

### 核心概念

* SQS 是 **分散式訊息排程系統**，用來做 **解耦與排隊處理**。
* 生產者（Producer）將訊息放入 queue，消費者（Consumer）依序讀取處理。

### 兩種模式比較

| 模式     | 特點                            | 適合情境                 |
| -------- | ------------------------------- | ------------------------ |
| Standard | 至少一次傳遞、**無順序保證**    | 一般用途，吞吐量高       |
| FIFO     | Exactly-once 傳遞、**保證順序** | 訂單處理、交易流程等場景 |

### 與 SNS 搭配 – Fan-out 模式

> ✅ **SNS 廣播 + SQS 多隊列接收 = Fan-out 模式（常考）**

### 使用情境

* 有多個服務需要異步處理同一事件。
* 每個服務擁有自己獨立的 SQS queue。

---

## 🔁 SNS + SQS 架構模式

### Fan-out 模式示意

```
  S3 ➝ SNS Topic ➝ [ SQS A, SQS B, Lambda ]
```

### 為什麼要這樣設計？

* SNS 負責廣播，SQS 幫你緩衝與解耦後續服務壓力。
* 可讓不同系統依自己的節奏處理訊息。
* 可擴充性高，每個 SQS queue 可對應不同微服務。

### 延伸應用

* S3 Notification ➝ SNS ➝ 多個 SQS：克服 S3 無法通知多端的限制。

> 📌 **考試技巧**：
> 題目如果提到“同一訊息要傳遞給不同系統、每個系統自己處理”，立刻想到 SNS + 多個 SQS 的 fan-out 架構！

## 🔄 Amazon Kinesis

### 核心概念

* Kinesis 是 AWS 提供的 **即時流式資料平台**，提供完整的數據管線解決方案。

### Kinesis Stream（資料流）

* 流資料會被分割到多個 **Shard**（分片），每個 shard 有固定的寫入/讀取頻寬。
* 可由多個應用程式同時讀取流資料。

### Shard 重點

> ✅ **Shard 是水平擴展單位，增加吞吐量的關鍵。**

### 模式比較：Provisioned vs On-Demand

| 模式        | 特點                        | 適用場景               |
| ----------- | --------------------------- | ---------------------- |
| Provisioned | 預設 shard 數量，需手動擴充 | 流量穩定、可預測應用   |
| On-Demand   | 自動擴展、依用量計費        | 不規則流量、高彈性需求 |

## 🔥 Kinesis Data Firehose

### 核心概念

* Firehose 是 **資料傳遞自動化服務**，無需管理基礎設施，將資料持續推送到目標（S3、Redshift、OpenSearch）。

### 與 Kinesis Stream 差異

| 服務           | 特點                               | 適用情境                 |
| -------------- | ---------------------------------- | ------------------------ |
| Kinesis Stream | 需要寫程式即時處理資料、具彈性     | 需客製處理邏輯、即時回應 |
| Firehose       | 管理型服務、自動處理、傳送到儲存端 | 資                       |
