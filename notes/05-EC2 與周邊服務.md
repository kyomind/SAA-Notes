# EC2 與周邊服務

2025-10-05

### 📌 EC2 Placement Groups：選對策略最關鍵

AWS EC2 提供三種 Placement Group 類型，針對不同架構需求選擇正確的方式：

| 類型            | 特性與用途                                                 |
| ------------- | ----------------------------------------------------- |
| **Cluster**   | 極低延遲、高頻寬需求（如 HPC、大型分散式應用）放在同一硬體內，速度快但風險集中。            |
| **Partition** | 把實例分成多個 Partition，彼此隔離，適合大型分散式架構（如 Hadoop、Cassandra）。 |
| **Spread**    | 每個實例分散在不同的硬體上，適合少量但需高可用的實例（如重要小型服務）。                  |

> 🧠 **考試提醒**：出現「需要高可用性」選 Spread，「大規模容錯」選 Partition，「低延遲/高頻寬」選 Cluster。

---

### 📌 ENI（Elastic Network Interface）

**ENI 就是 EC2 的虛擬網卡**，允許實例：

* 有多張網卡（多 ENI）
* 分流內外部流量
* 在實例間移動 IP（換網卡）

> 📎 **考試關鍵**：ENI 綁定在單一 AZ，無法跨 AZ 使用。題目提到多 AZ、跨區，要重新配置 ENI。

---

### 📌 EC2 Hibernate（休眠功能）

Hibernate 讓 EC2 暫停執行，**保留 RAM 狀態**，下次啟動可快速恢復。

* 適合：需要快速啟動、且希望保留執行狀態的應用程式
* 不等同於停止（Stop），Hibernate 還會保存記憶體快照

> 🧠 **考試提醒**：看到「快速恢復執行狀態」、「保留記憶體內容」就要想到 Hibernate。

---

### 📌 EBS（Elastic Block Store）核心觀念

* **類比**：EBS 就像雲端的網路硬碟
* 綁定 AZ，可跨實例掛載但**不能跨 AZ**直接使用
* 支援快照、加密、與 Volume 複製

#### 從快照恢復的延遲

* 官方說 24～72 小時完成資料預加載，但 **實際上通常幾分鐘內就能使用**，只是存取速度會慢一點。

> 📎 **考試提醒**：EBS Snapshot 恢復可以邊用邊讀，但效能會漸進改善。

---

### 📌 備份與恢復策略（AZ vs Region）

* 同一 Region 可跨 AZ 建立備援架構
* **若需跨 Region 備份**：要**手動複製快照**到其他 Region，再重建 Volume

> 🧠 **考試陷阱提醒**：EBS Snapshot 並**不自動跨 Region 備份**，要記得操作步驟。

---

### 📌 AMI（Amazon Machine Image）

**AMI 就是 EC2 的映像模板**，內含：

* 作業系統
* 應用程式
* 系統設定

#### 如何自訂 AMI？

1. 建立並設定一個 EC2
2. 將此實例建立為自訂 AMI
3. 日後可快速部署相同環境

#### 和 Docker image 的比較：

| 類型               | 層級  | 用途      | 包含內容               |
| ---------------- | --- | ------- | ------------------ |
| **AMI**          | 系統層 | VM 啟動模板 | OS + App + 設定      |
| **Docker Image** | 應用層 | 容器啟動模板  | App + Dependencies |

> 🧠 **理解類比有助考試**：AMI 就像 EC2 的 Docker Image，是整機環境的 snapshot。

---

### ✅ 小結：常見考點速記表

| 主題              | 關鍵記憶點                                   |
| --------------- | --------------------------------------- |
| Placement Group | Cluster = 快、Partition = 容錯、Spread = 高可用 |
| ENI             | 每張卡綁一個 AZ，跨 AZ 要重配                      |
| Hibernate       | 保留 RAM 狀態，快速恢復實例                        |
| EBS 快照          | 可邊讀邊恢復，但效能漸進式恢復                         |
| 跨 Region 備份     | Snapshot 要手動複製到其他 Region                |
| AMI vs Docker   | 類比理解，更易記住架構概念                           |

---

有了這些整理，你在看題目時應該能快速定位選項背後的設計原則，而不是靠死背。遇到模糊的題目，記得回到：**服務用途 + 架構目標 = 解題方向**。
