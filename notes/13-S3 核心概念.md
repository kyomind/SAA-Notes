# 13-S3 核心概念

2025-10-11

---

### 📌 基礎概念與服務本質

#### S3 是什麼？

Amazon S3（Simple Storage Service）是一個物件儲存服務，適用於儲存靜態檔案，例如圖片、影片、HTML 等等。

* **類比**：就像一個高可用、彈性、自動備份的雲端硬碟，或檔案伺服器。
* **常見用途**：

  * 網站靜態檔案託管
  * 備份與復原
  * 日誌與資料湖儲存

> 🧠 **考試提醒**：理解「物件儲存」與「區塊儲存（如 EBS）」的差異是 SAA 考試的基礎。

---

### 🪣 Bucket 命名規則

* **必須是全球唯一（globally unique）**

  * 因為 S3 的 URL 結構中會包含 Bucket 名稱（例如：https://`my-bucket`.s3.amazonaws.com）
  * 類似於網域名稱系統，需保證不衝突

> 📘 **補充**：AWS 背後有處理命名衝突的機制，只有一個用戶能成功註冊相同名稱

* **Cloudflare R2 的命名規則不同**

  * R2 的 Bucket 名稱只需在帳號範圍內唯一即可，**不需全球唯一**

---

### 🌐 靜態網站託管

S3 支援直接將 Bucket 設為靜態網站主機：

* 只需上傳 HTML、CSS、JS 檔案
* 啟用 "Static website hosting" 功能
* 可搭配 Route 53 + CloudFront 使用

> 🧠 **考試提醒**：遇到部署靜態網站需求的選項時，選擇 S3 是高機率正確答案

### 🔁 資料複製：CRR vs SRR

| 類型 | 全名                     | 複製範圍      | 使用場景           | 重點           |
| ---- | ------------------------ | ------------- | ------------------ | -------------- |
| CRR  | Cross-Region Replication | 跨 AWS 區域   | 災難復原、高可用性 | 提升地理冗餘   |
| SRR  | Same-Region Replication  | 同一 AWS 區域 | 法規遵循、帳務隔離 | 區域內資料備份 |

#### 設定 CRR / SRR 時的關鍵：

* **目標 Bucket 設定**
* **IAM Role 權限配置**（允許來源寫入目標）
* **篩選條件**（Prefix 或 Tag）
* **複製後儲存類別**（可選擇較便宜類型）

---

### 🧱 儲存類別（Storage Classes）

| 類別                 | 使用情境       | 成本     | 存取延遲             |
| -------------------- | -------------- | -------- | -------------------- |
| Standard             | 經常存取資料   | 高       | 低（即時）           |
| Intelligent-Tiering  | 存取頻率不穩定 | 自動調整 | 低                   |
| Standard-IA          | 偶爾存取資料   | 較低     | 低（但有取回費）     |
| Glacier              | 歸檔備份       | 非常低   | 幾分鐘到數小時       |
| Glacier Deep Archive | 長期冷備份     | 最低     | 最長（可達 12 小時） |

> 💡 **技巧記憶**：
>
> * 頻繁取用：用 Standard
> * 偶爾取用：用 IA
> * 幾乎不取：用 Glacier
> * 不想想太多：用 Intelligent-Tiering

---

### ⚖️ 可用性（Availability）vs 耐久性（Durability）

* **可用性**：資料在任何時刻是否「可以被存取」的機率
* **耐久性**：資料「長期保存不丟失」的機率

| 概念         | 定義         | S3 典型數值              |
| ------------ | ------------ | ------------------------ |
| Availability | 存取服務正常 | 99.99%（Standard）       |
| Durability   | 資料完整性   | 99.999999999%（11 個 9） |

#### 為何 S3 有超高耐久性？

* 自動複製多份資料
* 分散存放於多個 AZ
* 定期進行資料校驗與自動修復

> 📘 **延伸理解**：遠高於家用 NAS 或外接硬碟的備援能力，無需人為介入

---

### ✅ 總結：考試時的判斷關鍵

1. **靜態網站託管** → S3
2. **跨區域備援** → S3 + CRR
3. **不常存取的資料** → Standard-IA 或 Glacier
4. **需要自動成本優化** → Intelligent-Tiering
5. **資料不丟失最重要** → S3 十一個九的耐久性
